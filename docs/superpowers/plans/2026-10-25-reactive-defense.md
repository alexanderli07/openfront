# Reactive SAM reserve and coordinated actions

User approved: safe coastal opening 2 ports +1 city -> first SAM; then roughly4ports+3cities; build and preserve3m cash. Optional spending must leave reserve intact. Upgrade an existing SAM only for a currently incoming hostile strike when the model establishes that the upgrade changes interception from failure to success in time. Skip already-covered, impossible, late or uncertain strikes. Preserve existing frontline protection and disabled-building settings. Landlocked opening uses city/factory equivalents. Reserve remains latched after economic losses, with a replacement SAM allowed after SAM destruction.

Also authorized: stop duplicate automatic boat destinations and same-tick donations, add increasing cooldowns for unconfirmed transport targets, and remove the rule that freezes all development while saving for an island fleet. Manual transport actions remain unaffected. All money-consuming commands use actual quotes and a shared in-flight spending ledger, including warships and offensive weapons, so concurrent proposals cannot spend the same surplus twice.

Implementation units: command-guard (destination reservations/backoff and donation dedupe); defense-economy (stages and reserve); reactive-sam (conservative interception comparison); sam-defense-observer (normalize native trajectory/SAM state); shared spending ledger; central runtime/policy integration. Immutable vendor and generated artifact are not edited manually. Regression tests precede fixes, then full tests/scenarios/syntax/gateway audit/freshness. Record limitations explicitly: native carriers cannot be intercepted; uncertain or competing salvos are not grounds for speculative reserve spending.
