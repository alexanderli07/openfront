# Human targets and counterattack priorities

Migrate attackBestTarget and its difficulty-specific purpose order into explicit attack-plan candidates. Migrate incoming attacker, traitor, victim, very-weak, disconnected, hostile-relation and weakest target selection into attack-target candidates. Existing helpers remain callable through thin runtime adapters. This covers non-Bot player targets without incorrectly changing original enemy lists to humans-only.

Keep the original preflight order: structured bot opportunity, then optional priority counterattack. The priority counter bypasses general reserve/trigger gates and calls sendAttack(target,true,true). Normal counterattack remains inside the difficulty-specific order, calls counterReady then target selection and sendAttack(target,true), and retains the opening veto. After failed preflight, evaluate reserve and trigger/random gates once in the original order. The existing counterReady method retains absorb/peak/timer/shield state and math; its incoming-attacker lookup becomes a pure central target decision.

Attack purposes are lazy plans: candidates report readiness as unchecked until selected. Evaluating all routines eagerly would mutate diplomacy, consume RNG, perform searches and change readiness state. Retain exact original per-difficulty order and winFixes crater relocation. Selected routines evaluate their original preconditions, choose a target if relevant and attempt once. False advances to the remaining purposes; success stops. Explicit strategy wait stops the current attackBestTarget pass rather than bypassing a failed-plan signal and falling through to more attacks.

Target decisions record supplied input order, exact thresholds and measured values with exclusion reasons. Preserve incoming attack maximum individual troop count (not sum per attacker), positive-only and first tie. Preserve FFA strict versus inclusive comparisons: weak <15% capacity and <1.2x self; victim incoming >50% troops and <=1.2x self; traitor <1.2x self; disconnected <3x self; hostile <=3x self. Weakest is the original first input only. Counter readiness uses the existing target lookup but never dispatches. Live player objects stay outside the policy and return with original identity.

Bound target decisions to 79 candidates plus wait, ranked so the legacy winner is in the window; record total/visible/hidden counts. The default policy selects the earliest eligible input, except incoming sorted by descending individual attack troops. Extra policy decisions don't consume original RNG. Actual sendAttack and troop/boat behavior remain original. Async search results and command ownership are checked before executing. Target selection itself does not add new friendly filters that would silently change supplied enemy-list semantics; outbound safety remains in original sendAttack and the runtime owner guard.

Use scoped, restoring active-plan links: purpose -> target choice -> command; nested bot-target decisions must restore the enclosing purpose after return or exception. No global last-target cache. Record purpose outcomes, reserve/trigger gate outcomes and precise target-rule evaluations. A snapshot parentDecisionId links nested decisions without making a selector mutate execution context.

Exception for cancellation: a target policy wait/error within the synchronous counterReady lookup sets a stop signal scoped to the active attackBestTarget pass. That signal is checked before later purposes and cleared in finally; standalone lookups do not leave cancellation behind. No target or execution callback is stored in this scope.

Allies, betrayal, encirclement and island searches remain original executors selected as named purposes. Their internal algorithms, initial maybeAttack expansion/disconnected shortcut and navy targeting are not rewritten. This is an architectural migration, not combat or economy tuning.
